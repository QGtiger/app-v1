# 设计系统（Tailwind 4 CSS-first，重中之重）

## 色彩系统

整套设计**总共严格使用 3～5 种颜色**。

色彩结构要求：

- 选定 1 个主品牌色，贴合设计场景
- 搭配 2～3 个中性色（白、各级灰、米白、黑色变体）+ 1～2 个辅助色
- **未经用户许可，总颜色禁止超过 5 种**
- 不要大面积使用紫色，用户明确要求除外
- 修改组件背景色时，**必须同步调整文字色，保证对比度达标**

### 渐变规范

若无用户明确要求，**尽量不使用渐变，优先纯色**。
确需渐变：

- 仅作为细微点缀，不用于核心主元素
- 使用邻近色系渐变：蓝→青、紫→粉、橙→红
- **禁止冷暖对冲配色**：粉→绿、橙→蓝、红→青色等
- 色标最多 2～3 个，不使用复杂多阶渐变

## 排版规范
整套设计最多使用**2 种字体族**，字体过多视觉杂乱、拖慢加载。
字体结构：
- 标题字体（可使用多种字重）、正文字体各一种
- 禁止超过两种字体
排版实现规则：
- 正文行高 1.4–1.6，使用 `leading-relaxed` / `leading-6`
- 正文不要使用艺术字体，字号不得小于 14px

## 布局规范
**移动优先设计**，再针对大屏做增强适配。

## Tailwind 编写规范

布局优先级（严格按顺序选用）
1. Flex 弹性布局（绝大多数场景：`flex items-center justify-between`）
2. CSS Grid 仅用于二维复杂布局：`grid grid-cols-3 gap-4`
3. 除非别无选择，禁止 float、绝对定位

# 调试
- 先读代码 + `npx tsc --noEmit` + bash 排查，再决定改不改；不盲目改。
- 编译/HMR 报错：调 `dev_log`（返回末尾 100 行）。不必每次调——tsc 通过但预览异常、或改了 CSS/资源时再查。
- 运行时排查：用 `console.log("[v1] ...")` 打印日志追踪执行链路、查看变量、定位异常。日志带上下文、描述清晰，标明在校验什么。
  - 示例：`console.log("[v1] API call with params:", params)` / `console.log("[v1] State updated:", state)` / `console.log("[v1] Error:", err.message)`
  - 当前 agent 无法直读浏览器控制台（第二层未实现），需让用户把控制台输出贴回；第二层落地后 dev_log 可直接读。
  - 正常流程与异常都建议打；问题解决或转向其他需求后删除调试日志。
